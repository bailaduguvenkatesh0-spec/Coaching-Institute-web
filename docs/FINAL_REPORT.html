3. Project 1: Admissions Intelligence & Counsellor Routing

A. Multi-Channel Lead Ingestion & Normalization

  • Ingestion Channels: Public enquiry form (/enquire), REST API (POST /api/leads), n8n webhooks, CSV imports, and simulated channel events.
  • E.164 Phone Normalization: Strips whitespace/dashes, formats international standard (e.g., 98765-43210 → +919876543210).
  • Attribution-Preserving Deduplication: Identifies matches on Phone OR Email without creating duplicate pipeline cards. Updates existing lead attribution and records audit review.

B. Deterministic 0–100 Explainable Lead Scoring

Score = Course Completeness (25) + Start Date Proximity (25) + Consent (20) + Counselling Slot (15) + Stage (15)

Categories: Hot (≥70), Warm (40–69), Cold (<40). UI provides full factor breakdown drawers. Sensitive traits are strictly excluded.

C. Smart Routing & SLA Follow-up Engine

  • Routing Hierarchy: Course compatibility → Shift hours → Active workload capacity (< maxWorkload) → Deterministic tie-break → Fallback queue.
  • SLA & Cadence: Immediate 15-minute SLA Initial Contact task generated on ingestion. Follow-up cadences scheduled at +1, +3, and +7 days (maximum 3 attempts).
  • Quiet Hours (21:00–08:00 Asia/Kolkata): Outbound communications postponed during quiet hours.
  • Opt-Out Protection: Server-side check strictly blocks outbound messaging for opted-out candidates.

4. Project 2: Student Attendance & Explainable At-Risk Engine

A. Attendance Percentage Calculation Engine

Attendance % = ((Present Classes + Excused Classes) / (Held Classes - Excused Classes)) × 100

Documented, validated, and verified across all student metrics and reports. Excused absences prevent penalizing students for verified medical or family leave.

B. Staged CSV Import Engine

  • Supports attendance and assessment bulk imports with drag-and-drop file upload and CSV editor.
  • Dry-Run Preview: Validates student IDs, date formats, and duplicate rows without writing to DB.
  • Row-Numbered Diagnostics: Reports precise errors (e.g., Row 4: Unknown student ID TB-UNKNOWN-99).
  • Atomic Commit: Commits valid batches in a single transaction and triggers at-risk evaluations.

C. 5-Rule Explainable At-Risk Engine & Coordinator Tasks

Rule Code Trigger Condition Severity Automated Coordinator Action
CONSECUTIVE_ABSENCES 3 consecutive unexcused absences HIGH Creates 48h SLA task: Immediate guardian contact & wellness check.
LOW_ATTENDANCE_WINDOW <75% attendance in 30-day window MEDIUM Creates task: Mandatory academic counselling & parent review.
REPEATED_MISSED_CLASSES Consistent absence on specific weekdays LOW Creates task: Timetable conflict check with student.
MISSING_ASSIGNMENTS 3+ incomplete homework submissions MEDIUM Creates task: Faculty office hour assignment for tutorial assistance.
ASSESSMENT_DECLINE Score drop across 3 consecutive tests HIGH Creates task: Diagnostic test & remedial batch enrollment.

Staff can Resolve or Dismiss flags with documented audit notes. Record corrections automatically trigger metric reconciliation.

D. Gated Parent Outreach Queue

  • Weekly Summaries: Compiled strictly from verified DB records; deduplicated on (student, ISO week).
  • Consent Enforcement: Hard stop if guardian_preferences.consentGiven === false.
  • Staff Authorization Gate: Outreach requires authorized staff review and approval before dispatch.
  • Simulation Guard: Prominently badged SIMULATED to prevent accidental real-world SMS/WhatsApp charges in demo mode.
